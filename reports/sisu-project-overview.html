A · PROJECT OVERVIEW

What Sisu is, in one screen

Built for young Finnish adults who have a bank app full of numbers and nobody to tell them what the numbers mean.

The problem

A bank statement shows what happened. It does not say which bill is too high, what a habit costs in a year, or whether Friday's plan is safe. Advice apps guess, and chatbots invent figures.

What Sisu does

It sorts spending into S-Pankki's three baskets, finds the costly pattern, checks today's real prices on the web, and shows the saving with the transactions and pages behind it.

Why it can be trusted

Every number comes from code, never from the model. Code checks each figure the model says before it is shown or spoken. Actions are simulations that need an Approve tap and are logged.

The flagship 90-second judge experience

Times are suggested pacing for the presenter. The work itself is faster: a full plan took 3.4 to 6.7 seconds in today's final run.

What happened at about 14:40: the network dropped

During the latency run the laptop lost its connection for a few minutes. This was not planned, and it is the most useful thing the gauntlet found.

  • Worked: when the Verda GPU stopped answering, NVIDIA's hosted copy took over by itself and turns kept completing.
  • Did not work: while name lookups failed entirely, turns failed. Nothing can answer with no network.
  • Did not heal: the tunnel to the GPU stayed down until it was reopened by hand. The readiness check showed it at once.
  • After recovery: the re-run was clean: 0 errors, 1 turn of 35 on the backup.

Gaps and mismatches

  • A second plan can return actions that are already approved. Both clients already filter on "waiting", so nothing breaks.
  • Nobody calls the demo reset when a new visitor starts.

F · REMAINING PRIORITIES

The five things that matter before 10:00

In order. None of them is a backend defect that stops the demo; two of them can spoil it if left alone.

1
The flagship flow is not on the main screen yet

The web home page stops at the X-ray. The plan, the ask box and voice live on /plan and /dev/agent, and in the iOS app (verified in mock mode). Fix: lift /plan into the real screens, or decide now to demo from the iOS app or /plan, and rehearse that path against the live server.

HighOwner: frontend
Blocks the polished demo. /plan is the fallback.
2
The venue network can take the demo down

It dropped once today. Our GPU is reached through a tunnel that died with it. Fix: start the server with deploy/verda/dev-with-tunnel.sh or run keep-tunnel.sh beside it; keep a phone hotspot ready; open /dev/ready before each judge; record the backup video.

HighOwner: Nicholas
Blocks only if left alone.
3
Two backend pull requests are waiting

PR #4 (setup fees in offer ranking, one upstream call for many readers, cancelled plans) and this branch. They merge cleanly together and 270 tests pass with both. Fix: review and merge both, then restart the demo server.

MediumOwner: Nicholas
Does not block. The demo server needs the merge to have today's fixes.
4
The next visitor sees the last visitor's approvals

A bill is switched once, which is right, so a second visitor on the same customer has nothing left to approve until the demo is reset. Fix: call POST /api/demo/reset when a new visitor starts. Until that is wired, press "Reset demo" on /dev/ready.

MediumOwner: frontend, presenter
Does not block.
5
Live prices move, and voice is unproven on a real phone

Eetu's electricity saving was €23 a year in one search and €142 in another today, because the web returned different pages; each is real and sourced. Internet and mobile bills are guesses the customer confirms. Voice was not re-tested today. Fix: run the plan once before judging so the pages are warm, say "an estimate from today's prices" out loud, and test the microphone once on the phone over HTTPS.

MediumOwner: Nicholas
Does not block. Typed questions work without voice.
