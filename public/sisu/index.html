What runs behind every answer.

One rule holds the backend together.

  • The model chooses and explains.

    Nemotron picks from 14 tools and words the answer. It never does the sums.

  • Code computes.

    Every number comes from the finance engine or a page a tool fetched, and is checked before you see it.

  • You approve.

    The model can prepare an action. Only a button press carries it out.

Follow one question through the system.

“Find me a cheaper electricity deal and prepare the switch.”

  1. 1

    Speech to text. The recording goes to ElevenLabs and comes back as words.

    0.58 s
  2. 2

    Early start. A keyword check spots “cheaper electricity deal” and starts the offer research before the model has seen anything.

    under 1 ms
  3. 3

    The prompt. Fixed rules, then a summary of the customer worked out by the finance engine, then what Sisu remembers. No customer ID and no transaction rows.

    under 1 ms
  4. 4

    Nemotron decides. The model gets the prompt and the 14 tools, and asks for search_offers.

    first token 0.26 s
  5. 5

    Tools run. Exa finds today's comparison pages. Context.dev reads three at once into typed offers. Code works out each saving against the real bill.

    about 3 s
  6. 6

    The switch is prepared. The server builds the action from the offer it already holds, so the model cannot invent a price. It waits for approval.

    one model step
  7. 7

    The answer. Each finished sentence is checked against the receipts, then spoken, so speech starts before the answer ends.

    first audio 0.30 s
  8. 8

    Receipts. The turn ends with every number said and where it came from.

    one event
  9. 9

    Approval. You press Approve. A separate request marks the switch as carried out, in simulation, and adds two entries to the audit log.

Phone

Screens and cards

A web app and a native iOS app. Each draws one card for every event the server sends.

  • Stages, charts, lessons, the approval card and the receipts all arrive as events.
  • A “mock data” label shows whenever the server runs without keys.

app/ ios/Sisu/

Phone

useSisu hook

One hook gives a screen the whole conversation: the stages, the approval card, the lesson, memory and the receipts.

  • Every event is typed in lib/types.ts.
  • Works with no keys in mock mode, with the same events and timing.

lib/agent/useSisu.ts

Sisu server

API routes

Agent, voice, research, actions, memory, coach and health. A question goes in, a stream of events comes out.

  • POST /api/agent/query for typed questions, POST /api/voice/turn for speech.
  • POST /api/agent/plan builds a whole money plan in 5.7 to 7.6 s.
  • GET /api/health asks the model server which model it is serving.

app/api/

Sisu server

Orchestrator

Runs one turn as a loop of model steps: at most 4 for a question, 9 for an investigation.

  • Tools asked for in the same step run at the same time.
  • Slow work starts early. The model never waits for anything it did not ask for.
  • If research is not ready, a filler sentence is spoken so there is no silence.
  • More than 1,000 live turns streamed in one night, with 0 broken streams.

lib/agent/orchestrator.ts

Sisu server

Sentence check

Every sentence is checked before it is shown or spoken.

  • Catches a claim with no tool call behind it, a promise in place of work, and a number with no source.
  • A sentence that fails is thrown away, and the model tries again with a forced tool call.
  • At most two retries in a turn.

lib/agent/guards.ts

Sisu server

Number verifier

Checks every number the model says against the receipts its tools returned.

  • A figure copied with a slipped digit is replaced by the receipt's value.
  • Numbers written as words are checked like digits.
  • 0 of 142 numbers had no source on the closing run.

lib/agent/grounding.ts

Sisu server

Untrusted-text filter

Web pages, bill photos and pasted “instructions” are treated as data, never as orders.

  • Sentences that read like instructions to an assistant are removed from search excerpts.
  • A test bill carrying “Ignore all previous instructions” was read correctly.
  • Injection checks: 6 of 6.

lib/agent/tools/

Sisu server

Offer research

One shared run for each bill type and city, started before the model asks.

  • The early start, the app's prefetch and the model's tool call all join the same run.
  • A finished result is reused for 10 minutes and kept across restarts.
  • It waits for every page, up to 8.5 s, because the best offer changed when it answered from the first page alone.

lib/agent/research/ lib/agent/speculate.ts

Sisu server

Finance engine

Plain functions on the customer's own rows. Every number on the screen starts here.

  • The three baskets, safe to spend, cash flow to payday, nine kinds of pattern, affordability and three futures.
  • Each function takes under 0.4 ms.
  • Savings are never overstated: electricity use is estimated from the customer's own bill.

lib/finance/

Sisu server

Actions and approval

The model prepares a switch or a transfer. Only your button press carries it out, and in the demo that is a simulation.

  • The model has no approving tool. Tests offer it three, and all fail as unknown.
  • Approval is a separate request that names the customer.
  • An action expires after 30 minutes, because prices change.

lib/actions/

Sisu server

Memory

Sisu remembers only what the customer's own words support, and only with consent.

  • Which bill is which, yearly electricity use, preferences and goals.
  • Switching memory off erases what was stored.
  • A web page or a pasted instruction cannot plant a memory.

lib/memory/

Sisu server

State and audit log

One file, written in one go, with an audit log that shows if anyone has changed it.

  • Each entry stores the hash of the one before it.
  • Editing, removing or reordering an entry breaks the chain.
  • Three functions are the one place to put a database.

lib/store/

Sisu server

S-Pankki data

The synthetic transactions S-Pankki provided for the challenge.

  • Rows never leave the finance engine. The model sees totals.
  • Every read goes through one function, transactionsFor.
  • Tests confirm that no function returns another customer's rows.

lib/finance/data.ts

Our own GPU, Finland

Nemotron 3.5 Super VL

The only reasoning model. It runs on one GPU in Verda's FIN-02 data centre in Finland.

  • First token after 0.26 s.
  • The right tool in 27 of 27 checks on the closing run.
  • Chains five tools on its own in an investigation: 4.2 to 5.3 s.
  • Reads a photographed bill in about 1.5 s.

Sees: totals and a few selected facts. Never transaction rows or the customer ID.

lib/agent/model.ts deploy/verda/

Outside services

NVIDIA Build

The same model, as an automatic backup if our own GPU fails.

  • Takes over at once on an error, and after 2 s of silence.
  • After one failure, later steps go straight to the backup. A check every 5 s switches back.
  • With our GPU cut off, 6 of 6 turns were answered.

Sees: totals, only while our GPU is down. Never a bill photo.

lib/agent/breaker.ts

Outside services

Exa

Live search. It finds today's pages for every bill and every outside fact.

  • A search takes about 0.22 s.
  • Reads a page when Context.dev cannot.
  • Researches an open question across several sources in about 2.5 s.

Sees: a bill type and a city. Code writes the query.

lib/agent/research/exa.ts

Outside services

Context.dev

Turns a comparison page into typed offers: provider, plan, price per kWh, monthly fee and contract length.

  • Three pages at once, 2.8 to 3.3 s each.
  • The slowest stage, so it starts early and its results are shared.
  • A failed page is listed. No offer is invented.

Sees: the address of an offer page.

Good to know.

Straight answers before you try it.

Is Sisu a real S-Pankki service?

No. Sisu is a concept built at Junction 2026 for S-Pankki's challenge. It runs on synthetic data. It is not a service that S-Pankki offers.

Where does the data come from?

From synthetic data that S-Pankki provided for the challenge. No real customer's transactions are in it.

What does Sisu cost?

Nothing. The concept is free for customers, and nothing is locked behind payment.

Can spending break my streak?

No. The streak never depends on not spending, so buying something cannot break it. One tiny action a day keeps it going.

Does Sisu sell loans or credit?

No. Sisu never sells or markets loans, credit or pay-later, and it earns nothing from debt.
